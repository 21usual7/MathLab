# Качество обучения в MathLab

Рабочий критерий: после темы человек может объяснить переход рассуждения, проверить его условия и применить идею к изменённой задаче. Просмотр, число кликов, зелёная отметка и красота сцены сами по себе этого не показывают.

Это редакционный аудит содержимого репозитория, а не исследование результатов учеников. Оценки ниже — гипотезы для доработки и проверки с людьми.

## Аудит существующих уроков

| Урок / источник | Что уже помогает пониманию | Где есть риск | Следующее действие |
| --- | --- | --- | --- |
| Преобразования графиков — `js/topics/transform.js` | Одна отмеченная точка связывает вход, формулу и график; есть прогноз перед сдвигом и диагностические ошибки | Правило «внутри наоборот» легко заучить; заключительные задания в основном воспроизводят разобранные формы | Дать незнакомую функцию с известной точкой и потребовать найти её образ из уравнения для входа; отдельно проверить порядок двух преобразований |
| Производная — `js/topics/derivative.js` | Секущая, касательная, увеличение масштаба, построение графика наклонов; задания с объяснением ошибок | Вопрос о знаке предварялся готовым правилом и графиком ответа; гладкие примеры могли создавать впечатление «минимум ⇔ производная ноль»; перенос в измеряемые величины отсутствовал | В этой итерации: скрыть график до попытки, добавить два контрпримера, контролируемый эксперимент и оценку положения по скорости |
| Определитель — `js/topics/det.js` | Связанные площади разных фигур, сдвиг, разрезание параллелограмма, задачи с несколькими решениями | Формула называлась площадью без уточнения знака; семейство решений проверялось конечным списком точек | В этой итерации: различить ориентированную площадь и модуль; принимать всё семейство решений по математическому условию. Далее: ученик строит две разные матрицы с одним определителем и объясняет, какая информация потеряна |
| Хеши — `js/worlds/crypto/hashes.js`, `hash-process.js` | Видны вычисления; разделены учебный хеш, CRC и криптографический хеш; есть воспроизводимые атаки | Выполнение числовой цели ещё не проверяет, умеет ли человек выбрать механизм под новую угрозу; множество устройств может заслонить одну математическую идею | Отдельная задача: одинаковые данные/разные угрозы, выбор свойства и контрпример к неправильному выбору. Не увеличивать число алгоритмов до этой проверки |

ML сейчас развивается параллельно другим автором; этот аудит его не оценивает. XOR не является отдельной целью этой итерации.

## Контракт нового или переработанного урока

1. **Наблюдаемый результат.** Одно-два действия: объяснить, предсказать, построить контрпример, перенести. «Познакомиться с формулой» недостаточно.
2. **Содержательная задача.** Понятно, зачем понадобилась идея. До объяснения есть возможность сделать свою попытку. Предварительные знания названы и связаны ссылками.
3. **Причина перехода.** Формула и сцена отвечают на один вопрос. В последовательной анимации сначала исходное состояние, затем операция, затем следствие. Не каждый текстовый шаг нуждается в анимации.
4. **Управляемый эксперимент.** Названы фиксированные величины, изменяемая причина и наблюдаемый результат. Можно воспроизвести тот же исходный случай. Случайное движение ползунков не заменяет вопроса.
5. **Обоснование и границы.** Численный опыт отделён от доказательства. Для опасного обобщения дан контрпример; условия теоремы видны в объяснении.
6. **Обратная связь по рассуждению.** Ошибка показывает конкретное расхождение, а не только правильное число. Подсказка возвращает к причине. Равносильные ответы и целые семейства решений принимаются.
7. **Перенос.** Новые данные, представление или контекст; готового ответа нет в соседнем абзаце. Отдельно проверяется, когда идея неприменима. Успех в одном задании означает решение этого задания, а не доказанное владение темой.

## Как проверять с учениками

Короткая сессия с представителями аудитории, без подсказок автора:

- До урока дать небольшой прогноз и попросить объяснение; записать исходное рассуждение.
- В уроке попросить говорить вслух. Отмечать непонятные переходы и моменты, когда интерфейс мешает проверить мысль.
- После урока дать новую задачу без прежней сцены, а затем неверное обобщение для опровержения.
- Позже повторить перенос на другом примере. Различать самостоятельное решение, решение с подсказкой и воспроизведение ответа.

Пример для производной: после урока спросить, обязательно ли у минимума есть производная, достаточно ли нулевой производной для минимума, и как оценить изменение температуры по её текущей скорости. Попросить обоснование и назвать, каких данных не хватает для точного прогноза.

Пока таких сессий нет, можно утверждать только, что реализованы условия для самостоятельного рассуждения и проверены математика/интерфейс. Эффективность обучения ещё предстоит проверить.
