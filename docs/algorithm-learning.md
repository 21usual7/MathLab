# Алгоритмы: путь от математической причины к своему коду

В Topics → «Алгоритмы и структуры данных» доступны четыре новых модуля и переработанный бинарный поиск. Все уроки RU/EN. Маршруты работают и под префиксом GitHub Pages `/MathLab/`.

| Порядок | Тема | Математическая причина | Практика |
| --- | --- | --- | --- |
| 1 | `#topic/prefix-sums` | Дискретное накопление, разность, сокращение общего префикса | Суммы отрезков; адаптация LeetCode 303 |
| 2 | `#topic/two-pointers` | Монотонность таблицы сумм; неравенства исключают строки и столбцы | Пара в отсортированных данных; адаптация LeetCode 167 |
| 3 | `#topic/hash-two-sum` | x + y = t ⇔ y = t − x; память о просмотренном префиксе | Two Sum с исходными индексами; адаптация LeetCode 1 |
| 4 | `#topic/bracket-stack` | Баланс каждого префикса и вложенность; стек хранит больше, чем количество | Проверка скобок; адаптация LeetCode 20 |
| Затем | `#topic/binary-search` | Монотонный предикат, инвариант и убывающая длина | Свой lower_bound, дубликаты и граница n |

Структура новых модулей: прогноз → обратимая трассировка → математическое обоснование и контролируемая ошибка → Python → перенос без готового запуска. Прогноз и перенос проверяют также причину, а не только число. В эксперименте изменяется ровно одно условие или операция; отображается соответствующий код. Примеры включают отрицательные значения, повторы, пустые входы, невозможный ответ и ловушки границ. График накопления использует фиксированные шкалы во всех кадрах одного запуска.

Первая история бинарного поиска заменена управляемым сценарием: сравнение → самостоятельное обоснование сдвига → новое состояние. До верного обоснования следующий шаг не доступен. Элементы массива и возможные позиции границы показаны отдельно: `[lo, hi)` против `[lo, hi]`. Можно сменить порог, пройти назад, повторить состояние и изменить строку в причинном микроскопе. Автопрокрутки и обязательного ожидания анимации нет.

## Python

Редактор запускает настоящий CPython/WASM через Pyodide **0.27.7**, закреплённый CDN URL. Интерпретатор загружается только по нажатию запуска. При первом запуске нужен интернет; последующие загрузки используют HTTP-кеш браузера. Бэкенд и ключи не нужны. Код исполняется локально в отдельном Worker; это изоляция интерфейса, а не граница безопасности для враждебного кода.

- Черновик каждого урока сохраняется в localStorage; после перезагрузки восстанавливается. Недоступное хранилище не блокирует урок.
- Отдельные действия: запустить набор проверок; запустить свой пример с аргументами JSON; остановить; вернуть заготовку.
- stdout, ошибки синтаксиса и выполнения показаны текстом. Каждый непройденный пример показывает вход и расхождение. stdout ограничен 4000 символами.
- На загрузку интерпретатора отведено 45 секунд; на код и набор примеров — 3 секунды после загрузки. Stop, таймаут и уход из урока завершают Worker. После остановки можно запускать снова.
- Заготовка, памятка по Python, подсказка и разбор после двух попыток помогают ученику без опыта. Tab вставляет четыре пробела; Ctrl/Cmd+Enter запускает проверки. Native textarea сохраняет доступность и обычное редактирование на телефоне.
- Любая корректная пара разных индексов принимается, включая другой порядок индексов. Свой пример не засчитывает задание решённым.
- Проверки — открытые учебные примеры, не защищённый экзамен и не доказательство сложности или корректности для любых входов. Подходящую асимптотику ученик обосновывает инвариантом в уроке.

## Основания выбора

Темы выбраны как небольшой вводный маршрут по повторяющимся приёмам работы с массивами и памятью. Источники практики:

- [LeetCode Top Interview 150](https://leetcode.com/studyplan/top-interview-150/): ориентир по классическим типам задач, а не обещание полного покрытия программы.
- [MIT 6.006, материалы курса](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/download/): анализ алгоритмов, сортировка, хеширование и доказательство корректности. Наш короткий маршрут не является копией курса.
- [303 — Range Sum Query](https://leetcode.com/problems/range-sum-query-immutable/), [167 — Two Sum II](https://leetcode.com/problems/two-sum-ii-input-array-is-sorted/), [1 — Two Sum](https://leetcode.com/problems/two-sum/), [20 — Valid Parentheses](https://leetcode.com/problems/valid-parentheses/). Условия и примеры в MathLab написаны заново; отличия явно указаны. Например, функция вместо класса, индексы с нуля, допустимость отсутствия пары и пустого ввода.
- [Pyodide в Worker](https://pyodide.org/en/stable/usage/webworker.html): запуск Python отдельно от интерфейса. Документация stable развивается; реализация закреплена на проверенном 0.27.7 и его classic-worker API.

## Приёмка

`npm test` проверяет численные модели и сравнивает алгоритмы с независимыми оракулами, включая полный перебор коротких строк скобок. `CHROMIUM_PATH=/usr/bin/chromium npm run test:algorithms:browser` запускает сценарии в настоящем браузере: реальный WASM Python во всех пяти темах, неверный код, ошибки, бесконечный цикл, восстановление, Stop, свой пример, сохранение, уход со страницы, пути под `/MathLab/`, RU/EN и мобильные размеры с reduced motion. Для этих проверок нужен доступ к CDN интерпретатора. `npm run test:learning:browser` проверяет существующие учебные сценарии.

Для снимков интерфейса можно задать `ALGORITHM_SCREENSHOT=/tmp/algorithms.png`.

Результаты тестов подтверждают работу моделей и интерфейса. Качество усвоения требует сессий с учениками по [общему протоколу](learning-quality.md).
